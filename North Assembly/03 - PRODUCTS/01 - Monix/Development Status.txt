1. WHAT THIS DOCUMENT IS FOR
============================

This is the internal snapshot of where Monix currently stands.

It is meant to answer a practical question: what is working, what
is still being built, and what is not ready to be called finished?

It complements the Product Overview and Product Specification. It
does not replace either document.

The status written here should describe the project as it actually
is, rather than the state we would like it to be in.

6. RENDERING STATUS
===================

Monix uses a specialized rendering architecture built around Vulkan
and shader-based processing.

Current architectural areas include:

* Vulkan rendering.
* Dynamic Rendering.
* SPIR-V.
* Slang shaders.
* .slangp presets.
* Multi-pass processing.
* Runtime shader management.
* Shader cache.
* External texture handling.
* Feedback and pass-resource management.

[MANDATORY]
Rendering changes must preserve application stability and must not
knowingly compromise unrelated system functionality.

============================================================
7. SHADER STATUS
================

Shader processing remains an active development area.

Current functionality may include:

* Slang compilation.
* SPIR-V generation.
* Shader presets.
* Multi-pass pipelines.
* Dependency handling.
* Shader caching.
* Runtime loading.
* Validation.

[MANDATORY]
Shader resources must be validated before they are treated as valid
runtime resources.

[MANDATORY]
A shader failure must never be reported as successful initialization.

[RECOMMENDED]
Shader changes should be tested independently before being included
in a major product release.

============================================================
8. SHADER CACHE STATUS
======================

The shader cache exists to avoid recompiling the same work when the
relevant inputs have not changed.

Relevant cache information may include:

* Source content.
* Shader stage.
* Language.
* Compiler version.
* Dependency hashes.
* Manifest information.
* Integrity data.

[MANDATORY]
Cache entries must be invalidated when relevant source, dependency,
compiler, or compatibility information changes.

[MANDATORY]
Invalid or corrupted cache data must not be blindly trusted.

[RECOMMENDED]
Cache size should be controlled through an eviction strategy.

============================================================
12. SCRAM STATUS
================

SCRAM is the emergency-response subsystem used by Monix for defined
protective actions.

Current modes:

TEST
REAL

TEST mode exists for controlled testing.

REAL mode is intended for actual response actions and therefore
requires the appropriate validation and authorization.

[MANDATORY]
TEST mode must not intentionally execute actions exclusive to REAL
mode.

[MANDATORY]
The active SCRAM mode must always be identifiable to the User.
