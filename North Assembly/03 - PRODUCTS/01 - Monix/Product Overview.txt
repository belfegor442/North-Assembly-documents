PRODUCT IDENTITY

Monix is a North Assembly desktop software project focused on system monitoring, logging, diagnostics, configuration, security-oriented analysis, state handling, and a highly customized visual interface.

The product is intended to bring these functions together without sacrificing the accuracy of the information being shown.

PRODUCT OBJECTIVE

Monix is being developed as a structured environment for understanding what is happening on a computer and presenting that information through a unified interface.

The product prioritizes:

* Reliability.
* Clear system information.
* Consistent monitoring.
* Controlled configuration.
* Diagnostic visibility.
* Security-conscious operation.
* A distinctive visual identity.

CORE FUNCTIONAL AREAS

Monix may provide functionality across:

* Logging.
* Task and process information.
* CPU monitoring.
* RAM monitoring.
* GPU monitoring.
* Temperature monitoring.
* Disk monitoring.
* Network monitoring.
* System usage.
* Diagnostics.
* Security-oriented analysis.
* Configuration.
* State and snapshots.
* Event visualization.
* Rendering and visual effects.
* Shader processing.

The interface may evolve as development continues.

[MANDATORY]
Major interface changes must remain consistent with the product's purpose and usability requirements.

MONITORING

Monix may obtain CPU, memory, GPU, temperature, storage, network, process, and other supported system information.

[MANDATORY]
Monix must not intentionally present fabricated information as genuine telemetry.

[MANDATORY]
Monitoring must fail safely when required information is unavailable.

[RECOMMENDED]
Measured, derived, estimated, stale, and unavailable information should remain distinguishable where applicable.

LOGGING

Logging is a core Monix subsystem. It may record system events, application events, warnings, errors, diagnostics, security events, state changes, and monitoring events.

[MANDATORY]
Logs must accurately represent the source and severity of events.

[MANDATORY]
Security-sensitive information must be handled according to the North Assembly Security Policy.

TASKS AND PROCESSES

The TASKS functionality may show process names, identifiers, resource usage, state, executable information, and supported security classifications.

[MANDATORY]
Monix must distinguish information it can verify from information it cannot reliably determine.

[MANDATORY]
Actions affecting processes or system state require the appropriate authorization.

SYSTEM USAGE

USAGE provides an overview of CPU, RAM, GPU, storage, network, and temperature information.

[MANDATORY]
Displayed measurements must correspond to the available system data and its technical limitations.

SECURITY AND ANALYSIS

Monix may include reputation analysis, heuristic analysis, suspicious-activity detection, security-event monitoring, and protective response mechanisms.

[MANDATORY]
Heuristic or probabilistic detections must not be presented as certain facts without independent evidence.

[MANDATORY]
Protective actions must remain within the permissions and authorization available to the application and operating system.

SCRAM

SCRAM is Monix's emergency-response subsystem for defined protective actions.

Operational modes include:

* TEST.
* REAL.

[MANDATORY]
TEST mode must not knowingly perform actions reserved for REAL mode.

[MANDATORY]
REAL mode must only execute actions for which the required authorization exists.

[RECOMMENDED]
High-impact actions should clearly identify the active mode and include safeguards against accidental activation.

STATE AND SNAPSHOTS

Monix may capture selected application and system state for diagnostics, comparison, support, development, or controlled recovery.

[MANDATORY]
A snapshot must not be described as a complete system backup unless it actually provides that functionality.

[RECOMMENDED]
Snapshots should include enough metadata to establish when and under which relevant configuration they were created.

RENDERING

Monix uses a specialized rendering environment based around Vulkan and shader processing.

Relevant technologies may include:

* Vulkan.
* SPIR-V.
* Slang shaders.
* Multi-pass rendering.
* Shader presets.
* Runtime shader management.
* Shader caching.

[MANDATORY]
Rendering failures must not intentionally compromise unrelated system functionality.

SHADER SYSTEM

Monix may support .slang, .slangp, and SPIR-V resources.

[MANDATORY]
Shader resources must be validated before runtime use.

[MANDATORY]
Shader processing must respect applicable licenses and security boundaries.

CONFIGURATION

Configuration may control interface behavior, monitoring, logging, rendering, security, performance, shaders, updates, AI, and diagnostics.

[MANDATORY]
Configuration changes must not silently modify unrelated critical system behavior.

[RECOMMENDED]
Configuration options should explain their effects where those effects are not obvious.

PERFORMANCE

Monix is intended to operate efficiently within its supported use cases.

[MANDATORY]
Performance optimizations must not knowingly sacrifice critical reliability or security.

ERROR HANDLING

[MANDATORY]
Expected errors must be handled without intentionally exposing sensitive information.

[MANDATORY]
Critical failures must never be reported as successful operations.
