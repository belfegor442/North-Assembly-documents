============================================================
1. PURPOSE
============================================================

This Policy defines the general security requirements for Weird
Stuff systems, products, infrastructure, accounts, repositories,
information, and internal operations.

Its purpose is to protect:

* North Assembly systems.
* Products and source code.
* Internal information.
* User information.
* Credentials and secrets.
* Infrastructure.
* Service availability and integrity.
* Members and authorized collaborators.

============================================================
2. SCOPE
============================================================

This Policy applies to:

* North Assembly personnel and collaborators.
* Internal accounts.
* Development environments.
* Production environments.
* Source-code repositories.
* Infrastructure.
* Corporate communication systems.
* Product distribution systems.
* Credentials and secrets.
* Systems that store or process sensitive information.

[MANDATORY]
Anyone granted access to North Assembly resources must follow the
security requirements that apply to that access.

============================================================
3. SECURITY PRINCIPLES
============================================================

North Assembly's general security principles are:

* Least privilege.
* Need-to-know access.
* Defense in depth.
* Secure configuration.
* Separation of environments.
* Traceability of important actions.
* Credential protection.
* Timely incident response.

[MANDATORY]
Security controls must not be intentionally bypassed without proper
authorization.

============================================================
4. ACCESS CONTROL
============================================================

[MANDATORY]
Access must only be granted for a legitimate operational reason.

[MANDATORY]
Permissions must be limited to the minimum reasonably necessary.

[MANDATORY]
Administrative privileges must be restricted to authorized people.

[MANDATORY]
Access must be revoked when it is no longer required.

[RECOMMENDED]
Access to critical systems should be reviewed periodically.

============================================================
5. ACCOUNTS
============================================================

[MANDATORY]
Where technically possible, each person must use an individual
account.

[MANDATORY]
Credentials must not knowingly be shared, and users must not
knowingly allow another person to use their authenticated account.

[MANDATORY]
Default passwords must be changed when applicable.

[RECOMMENDED]
Critical accounts should use multi-factor authentication.

============================================================
6. PASSWORDS AND AUTHENTICATION
============================================================

[MANDATORY]
Passwords must be protected against unauthorized disclosure.

[MANDATORY]
Passwords must not be stored in plain text when secure credential
storage is technically available.

[MANDATORY]
A compromised or suspected-compromised password must be changed or
invalidated as soon as reasonably possible.

[RECOMMENDED]
Important accounts should use unique passwords and, where available,
a trusted password manager.

============================================================
7. API KEYS, TOKENS, AND SECRETS
============================================================

Secrets include API keys, access tokens, private keys, signing keys,
passwords, database credentials, service credentials, and other
authentication secrets.

[MANDATORY]
Secrets must not intentionally be committed to public repositories.

[MANDATORY]
Secrets must not be unnecessarily distributed through chat, public
documents, screenshots, or other exposed channels.

[MANDATORY]
Suspected compromised secrets must be rotated, revoked, or otherwise
secured.

[RECOMMENDED]
Dedicated secret-management systems should be used where practical.

============================================================
8. SOURCE CODE SECURITY
============================================================

[MANDATORY]
Source code must be stored in authorized repositories.

[MANDATORY]
Private repository access must be limited to authorized people.

[MANDATORY]
Security-sensitive code should receive appropriate review before
release where the team structure permits.

[MANDATORY]
Known critical vulnerabilities in production code must be assessed
and addressed appropriately.

[RECOMMENDED]
Automated security analysis should be used where practical.

============================================================
9. DEPENDENCY SECURITY
============================================================

[MANDATORY]
Important third-party dependencies must be identifiable.

[MANDATORY]
Dependencies should be obtained from reasonably trustworthy sources.

[MANDATORY]
Known severe security issues in dependencies must be assessed.

[MANDATORY]
Software licenses must be respected.

[RECOMMENDED]
Dependency updates and vulnerability monitoring should be automated
where practical.

============================================================
10. DEVELOPMENT ENVIRONMENTS
============================================================

[MANDATORY]
Development environments must not unnecessarily contain production
credentials or sensitive production data.

[MANDATORY]
Production credentials should not be reused for ordinary development
when separate credentials are technically possible.

[RECOMMENDED]
Development, testing, and production environments should be separated.

============================================================
11. PRODUCTION ACCESS
============================================================

[MANDATORY]
Production access must be limited to authorized personnel.

[MANDATORY]
Production systems must not be modified without an appropriate
operational reason.

[MANDATORY]
Security-sensitive production changes should be traceable where
technically possible.

[RECOMMENDED]
Production administrative access should use stronger authentication
and logging controls than ordinary access.

============================================================
12. INFRASTRUCTURE SECURITY
============================================================

[MANDATORY]
Critical infrastructure must use reasonable security controls suited
to its function.

These may include:

* Authentication.
* Authorization.
* Network controls.
* System hardening.
* Logging.
* Monitoring.
* Backups.
* Patch management.

Detailed infrastructure architecture, providers, and hosting
locations remain pending and must be documented separately where
necessary.

============================================================
13. SOFTWARE UPDATES
============================================================

[MANDATORY]
Operating systems, infrastructure software, and critical dependencies
must be updated when security updates are necessary and reasonably
available.

[MANDATORY]
Known high-risk vulnerabilities must not be knowingly ignored without
an assessed reason.

[RECOMMENDED]
Critical security updates should take priority over non-critical
maintenance.

============================================================
14. LOGGING AND MONITORING
============================================================

[MANDATORY]
Important security events should be recorded where technically
necessary and legally appropriate.

Relevant events may include:

* Authentication events.
* Administrative actions.
* Security alerts.
* Configuration changes.
* Failed access attempts.
* Significant application errors.

[MANDATORY]
Security logs must not be publicly exposed without authorization.

Logging retention requirements remain to be defined according to the
actual systems involved.

============================================================
15. MALWARE PROTECTION
============================================================

[MANDATORY]
Software and infrastructure must not knowingly be configured to
facilitate unauthorized malware deployment.

[MANDATORY]
Suspected malicious software must be isolated, investigated, and
removed or contained where appropriate.

[RECOMMENDED]
Development and production systems should use appropriate malware and
endpoint protections where available.

============================================================
16. VULNERABILITY MANAGEMENT
============================================================

[MANDATORY]
Known vulnerabilities affecting North Assembly systems must be assessed
according to their severity and potential impact.

A vulnerability may be classified as:

* Critical.
* High.
* Medium.
* Low.

[MANDATORY]
Critical security vulnerabilities must be prioritized.

[RECOMMENDED]
Important products should use a vulnerability-tracking system.

============================================================
17. SECURITY REPORTING
============================================================

[MANDATORY]
Anyone who becomes aware of a potentially serious security issue
should report it through an authorized channel as soon as reasonably
possible.

---

============================================================
18. SECURITY INCIDENT RESPONSE
============================================================

Security incidents should generally follow this sequence:

1. Detection.
2. Assessment.
3. Containment.
4. Eradication.
5. Recovery.
6. Verification.
7. Documentation.
8. Preventive action.

[MANDATORY]
Reasonable measures must be taken to limit the impact of a confirmed
serious security incident.

[MANDATORY]
Relevant evidence must not be intentionally destroyed when preserving
it is necessary for investigation or legal compliance.

[RECOMMENDED]
Significant incidents should receive a post-incident review.

============================================================
19. ACCOUNT COMPROMISE
============================================================

When an account is suspected of compromise, the responsible team
should, as appropriate:

* Restrict access.
* Reset credentials.
* Revoke sessions.
* Revoke tokens.
* Review relevant activity.
* Restore secure access.
* Assess potential impact.

[MANDATORY]
A compromised account must not continue to be used normally while
the compromise remains unresolved.

============================================================
20. DATA PROTECTION
============================================================

[MANDATORY]
Personal and sensitive information must receive protection
appropriate to its nature and risk.

[MANDATORY]
Access must be limited according to operational need.

[MANDATORY]
Sensitive information must not be publicly disclosed without proper
authorization and a lawful basis where applicable.

The detailed requirements for personal data are defined in the
Privacy Policy.

============================================================
21. BACKUPS
============================================================

[MANDATORY]
Critical information must have reasonable recovery mechanisms where
technically possible.

[RECOMMENDED]
Important backups should be:

* Separate from the primary system.
* Access-controlled.
* Protected against accidental deletion.
* Tested for recoverability.

The final backup architecture remains pending.

============================================================
22. DISASTER RECOVERY
============================================================

[MANDATORY]
North Assembly must maintain reasonable capabilities to recover critical
systems from significant failures where technically possible.

Potential scenarios include:

* Infrastructure failure.
* Repository loss.
* Credential compromise.
* Data corruption.
* Provider outage.
* Security incident.

[RECOMMENDED]
Recovery procedures should be documented and periodically tested.

============================================================
23. THIRD-PARTY SECURITY
============================================================

[MANDATORY]
Third-party services with significant access to North Assembly systems
or information must be considered from a security perspective before
use.

[MANDATORY]
Third parties must not receive unnecessary access.

[RECOMMENDED]
Critical providers should be reviewed periodically.

============================================================
24. PHYSICAL SECURITY
============================================================

Where North Assembly operates or stores systems in physical locations:

[MANDATORY]
Reasonable measures must be taken to prevent unauthorized physical
access to critical systems and storage.

Specific physical-security requirements depend on the actual hosting
and equipment model used by North Assembly.

============================================================
25. SECURITY OF RELEASES
============================================================

[MANDATORY]
Published software must be distributed through authorized channels.

[MANDATORY]
Release artifacts must not knowingly be altered after release
without appropriate version control.

[MANDATORY]
Automatic update systems must use reasonable integrity and
authenticity protections.

[RECOMMENDED]
Release signing should be implemented for important products where
technically possible.

============================================================
26. SECURE DEVELOPMENT
============================================================

[MANDATORY]
Security must be considered during the design and development of
products that process sensitive information or expose
security-relevant functionality.

[RECOMMENDED]
Security reviews should be performed before major releases.

[RECOMMENDED]
Where appropriate, security testing should cover:

* Authentication.
* Authorization.
* Input validation.
* Dependency analysis.
* Configuration.
* Abuse cases.

============================================================
27. SECURITY EXCEPTIONS
============================================================

[MANDATORY]
A deviation from a mandatory security requirement must be authorized
by an appropriate authority.

[MANDATORY]
A security exception must not become permanent unless the underlying
policy is formally changed.

[RECOMMENDED]
Significant security exceptions should be documented.

============================================================
28. SECURITY RESPONSIBILITIES
============================================================

Security responsibilities follow the existing organizational
structure.

CEO:
Overall executive authority.

Director:
Operational oversight.

Manager:
Operational coordination.

Specialized teams:
Security responsibilities within their technical or operational
areas.

[MANDATORY]
Everyone with access to North Assembly systems is responsible for
following the security requirements applicable to their role.

============================================================
29. SECURITY AWARENESS
============================================================

[RECOMMENDED]
People with access to critical systems should receive basic guidance
on:

* Credential protection.
* Phishing.
* Social engineering.
* Account security.
* Secure information handling.
* Incident reporting.

============================================================
30. SECURITY AUDITS AND REVIEWS
============================================================

[RECOMMENDED]
Security controls should be reviewed periodically.

Reviews may include:

* Account permissions.
* Credentials.
* Dependencies.
* Vulnerabilities.
* Infrastructure.
* Backups.
* Logs.
* Release mechanisms.

[MANDATORY]
Critical security problems identified during a review must be
communicated to the appropriate authority.

============================================================
31. PUBLIC DISCLOSURE
============================================================

[MANDATORY]
Internal security architecture, credentials, private keys, security
configurations, private infrastructure information, and other
sensitive security information must not be publicly disclosed without
authorization.

[MANDATORY]
Public security statements must not knowingly misrepresent the
security properties of a North Assembly product or service.

* Major infrastructure changes occur.
* A significant security incident occurs.
* Major products are introduced.
* Security requirements materially change.
* Internal security responsibilities change.

[RECOMMENDED]
A periodic general review should also be performed.
